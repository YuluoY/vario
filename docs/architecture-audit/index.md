## 一句话结论

当前实现只适合**可信 Schema、低频更新、约 200 节点以内的内部原型**；即使是小页面，要生产发布也必须先修复本报告 P0。完成 Phase 0～2 后，才能逐步承载 200～1000 节点的中型后台页面。它**尚不能按现状作为中大型、多页面、可编辑画布或不可信租户 Schema 的生产核心**。

阻断原因不是单一“性能不够”，而是四类问题叠加：

1. 当前工作树已有循环作用域正确性回归，核心与 Vue 测试均失败。
2. 状态更新仍触发整棵 Schema 的 VNode 重建，循环与 parentMap 路径存在 O(N) / O(N²) 热点。
3. Schema 的类型、验证、规范化、运行时并非同一契约，合法字段会丢失，非法 action 又可能通过。
4. 不可信 Schema 可触发原型污染、表达式副作用与超时后继续写状态，安全边界不成立。

## 适用性矩阵

| 场景 | 当前结论 | 上线条件 |
|---|---|---|
| ≤200 节点、≤80 唯一表达式、无大循环 | 有条件可用 | 先修 P0；Schema 可信；监控错误与长任务 |
| 200～1000 节点的表单/后台页 | 有条件可演进 | 完成 Phase 0～2；状态更新必须局部化 |
| 1000+ 节点或 500+ 行列表 | 不建议 | 编译计划、稳定子树、虚拟化、性能门禁全部落地 |
| 画布内高频增删改节点 | 不可用 | 稳定 Node ID、增量编译、可回滚 patch、Worker 校验 |
| 10～20 个页面同时驻留 | 仅简单静态页可跑 | PageSession 生命周期、暂停/销毁、资源预算与隔离 |
| 第三方/租户可提交 Schema | 禁止 | 路径、表达式、action、能力权限与配额全部加固 |
| SSR / hydration | 未达到生产保证 | 消除全局可变注册表与上下文泄漏，增加 SSR 契约测试 |

这里的节点数是校准尺度，不是通用 SLA。组件库组件、图表、富文本、复杂 slot 的成本远高于原生 DOM；最终门槛应以 [验收门禁](./acceptance-gates.md) 的场景基准为准。

## 本次判断的边界

- 不使用 README、现有性能说明或注释中的“快”“安全”“O(1)”作为证据。
- 注释与实现冲突时，以源码执行结果为准。
- 浏览器数据来自同一台机器上的 Headless Chrome 151、Vue 3.5.27，只用于识别增长趋势和断点，不用于跨设备营销对比。
- 当前工作树在审计开始前已有未提交改动。本报告不覆盖、不回退这些改动，并明确把它们计入当前可发布状态。
- 本轮交付是审计与可执行设计，不批量重写生产内核；大规模重构必须按路线图先补安全网。

## 立即决策

在完成 [实施路线图 Phase 0](./implementation-roadmap.md#phase-0-生产阻断修复) 前：

- 不发布当前 `core/vue/schema/cli` 版本。
- 不接入可由终端用户或第三方编辑的 Schema。
- 不把现有性能测试结果作为中大型页面容量证明。
- 不在画布中依赖 `findById(...).patch(...)` 或嵌套对象原位修改自动刷新。
- 不承诺 `batch` 原子性、VM 超时后停止副作用、循环别名可用或 lifecycle 只挂载一次。
